# 项目 README

## 项目简介
一个基于 Go 的模块化单体（modular monolith）示例项目，实现多角色订单系统：普通用户可下单，运营 / 管理员可管理订单与用户。各业务模块边界清晰，通过明确的接口通信，便于后续演进为微服务。

## 技术栈
- 语言：Go（模块化单体架构）
- ORM：GORM（统一使用泛型 API）
- 目录结构遵循标准 Go 项目布局

## 目录结构
```
.
├── cmd/
│   └── server/          # 服务入口，程序启动与路由装配
├── internal/
│   ├── user/            # 用户与角色（普通用户 / 运营 / 管理员）、权限
│   └── order/           # 订单领域：状态机、订单归属用户
├── go.mod
└── go.sum
```

## 业务模块说明
- **user 模块**：管理用户账户、角色与基础权限，对外提供用户查询与鉴权相关接口。
- **order 模块**：管理订单生命周期（待支付 → 已支付 → 已发货 → 完成 / 退款），订单与用户模块通过明确接口关联。

## 模块依赖约定
- `order` 可依赖 `user`（如下单时归属用户）；`user` 不反向依赖 `order`，保持依赖单向。
- 跨模块调用仅通过各模块导出的接口，不直接访问对方内部实现。

## 开发规范
详见 `AGENTS.md`，核心要点：
- 代码遵循 `gofmt` 格式，注释使用中文。
- GORM 一律使用泛型 API，禁止传统非泛型写法。
- 改动前先确认方案，仅生成最小脚手架。
